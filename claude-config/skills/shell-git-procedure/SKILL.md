## 1. rc 를 볼 자리엔 파이프를 붙이지 않는다

```bash
# ❌ 파이프가 rc 를 먹는다 — 파이프라인의 rc 는 마지막 명령(tail)의 것
git commit -F msg.txt file.sh | tail -2 && git push     # commit 이 실패해도 push 가 돈다

# ✅ rc 를 먼저 받는다
git commit -F msg.txt file.sh
rc=$?; echo "commit rc=$rc"
[ $rc -eq 0 ] || exit 1
git push
```
실제 사고: `commit` 이 untracked pathspec 으로 실패했는데 `&&` 가 못 보고 **빈 브랜치를 push** 했다.
`set -o pipefail` 도 방법이지만, **rc 를 눈으로 찍는 쪽**이 더 확실하다(끄고 켜는 상태에 안 의존).

### 1-b. 🔴 출력이 «비었을» 때는 결론을 내기 전에 rc 를 «먼저» 본다

빈 출력은 **「어긋남 0건」과 「아예 안 돌았다」를 뭉친다.** 검사·census·`diff` 처럼 **부재가 곧 초록**인 명령일수록 위험하다 — 그 자리에서 빈 출력은 **원하는 답과 똑같이 생겼다**.

```bash
# ❌ 「0건이네, 통과」 — 실은 rc=127 (명령을 못 찾음)
./scripts/lint-nino-memory.sh
# (출력 없음)

# ✅ 부재를 읽기 전에 rc 를 찍는다
./scripts/lint-nino-memory.sh; rc=$?
echo "lint rc=$rc"          # 0=진짜 0건 · 1=위반 · 127=안 돌았다 · 2=판정 불가
```

🔑 **가드를 「`cd` 조심」으로 적으면 안 된다 — `cd` 의 persist 여부가 «조건부»다.**

```
cd <작업 디렉터리 «안»>   → 다음 호출까지 «유지된다» (조용히)
cd <작업 디렉터리 «밖»>   → 되돌아간다 + `Shell cwd was reset to ...` 가 찍힌다
```
🔴 **실측 2026-08-11 — 양쪽 봇 하네스가 «같은» 규칙이다.** 나는 처음에 *「룬드는 persist, 나는 매번 리셋 — 방향이 반대」*로 적었는데 **둘 다 틀렸다**: 내 쪽도 `discord-bot-nino/scripts` 로 들어가면 다음 호출에서 그대로 남는다. 「리셋된다」는 인상은 **내가 밖(`/tmp`·다른 레포)으로만 나가봐서** 생긴 것 — 표본이 한쪽이었다.
🔑 **그래서 「리셋해주니 안전하다」는 감각이 나머지 절반에서 정확히 실패한다**(룬드 문장). **부분 안전장치는 «없는 것으로 치고»** `cd` 를 아예 안 쓴다 — **`git -C <경로>` + 절대경로**. 그리고 rc 를 본다.

🔴 **rc 만으로도 모자란 자리가 있다 — `0` 이 «값»으로 나오는 루프.** 「전부 0줄」은 **결과처럼 생겼다**. rc 와 **stderr 를 같이** 본다.

```bash
# ❌ 한글 경로가 8진 이스케이프 + 따옴표로 나와서, 그 이름으로 다시 부르면 전부 실패한다
git ls-tree --name-only HEAD memory/principles/   # → "memory/principles/01-\354\236\254...md"
# 이걸 그대로 git show 에 넘기면 → rc=128, fatal: path ... does not exist  (루프는 0 만 아홉 줄 찍는다)

# ✅ 사람이 읽을 목록이면
git -c core.quotePath=false ls-tree --name-only HEAD memory/principles/

# ✅✅ 목록끼리 «대조»할 거면 -z (따옴표 자체가 안 생긴다 — 2026-08-01 채택한 형태)
git ls-files -z | while IFS= read -r -d '' f; do ...; done
```
🔴 **`?`·`*` 가 든 인자는 «항상» 따옴표로 싼다** — `gh api repos/o/r/contents/x.py?ref=abc` 가 **zsh 에선 `no matches found` 로 죽는다**(글롭). 🔑 **내 bash 는 `failglob`·`nullglob` 이 꺼져 있어 미매치가 그대로 통과하므로 «조용히 안 걸린다»** — 노출 0 인 이유가 「내가 조심해서」가 아니라 **「bash 기본값이 관대해서」**다. 공유 코어 스크립트는 룬드 zsh 에서도 도니 남 일이 아니다. ⚠️ 리다이렉트가 이미 열려 있으면 **빈 파일**이 남아 diff 가 「전부 추가」로 보인다 — **0 이 아니라 «못 읽은 것»인데 화면은 정상 결과처럼 생겼다.**

기본값이 `core.quotePath=true` 라 **설정 안 한 환경이 전부 해당된다**(2026-08-11 내 WSL 에서 재현: rc=128 · `fatal: path … does not exist`). `principles/01-재기-전.md` 처럼 **우리 문서 경로가 대부분 한글**이라 남 일이 아니다.

### 1-c. 🔴 줄 수는 `wc -l` 로 센다 — 파이썬 `len(split("\n"))` 금지

파일이 개행으로 끝나면 `split` 이 **빈 조각을 하나 더** 만들어 **+1** 이 된다.

```python
len(open(p).read().split('\n'))   # ❌ 개행으로 끝나면 +1
sum(1 for _ in open(p))           # ✅ wc -l 과 같다
```
- ✅ **델타는 이 오차에 면역, 절대값은 아니다** — 전후가 같이 +1 이라 상쇄된다.
  그래서 **`-1170` 같은 델타는 살고 `1838` 같은 절대 줄수만 죽는다.**
- ✅ **검산 한 번**: 부분들과 합계가 같은 문서에 있으면 **더해본다**.
  차가 **항목 수의 배수**면 그게 곧 진단이다(`6638 − 6629 = 9 = 권수` ⇒ 「권마다 +1」).
- 🔴 실측 2026-08-11 — **하룻밤에 네 번** 났다(룬드 `1838` · 내 `865줄` 등).
  진단하고 계약에 올린 **직후에도** 밟았다 ⇒ **「알고 있다」가 처방이 아니다.**

## 2. 진단·판정에 쓸 출력에서 **«내가 버린 게 있나»**를 먼저 본다

🔴 **좌변은 «도구 이름»이 아니다.** 옛 제목은 ~~「`| head` 를 붙이지 않는다」~~ 였는데, 그러면 **다음 도구에서 그대로 빈다** — 실물 2026-08-22: `gh api … --jq '.[] | "\(.body[0:700])"'` 로 코멘트를 읽고 **「이 코멘트엔 그 내용이 없다」**는 틀린 결론을 냈다. 찾던 절이 **700자 밖**이었고, `head` 가 아니라 **`jq` 슬라이스**라 이 절에 안 걸렸다. (룬드도 **같은 코멘트**를 `[0:700]` + `tail -25` 로 **두 번** 잘라 같은 결론에 갔다 — 둘 다 열었고 둘 다 못 봤다.)

**걸리는 것 전부**: `head`/`tail` · `jq` 의 `[0:N]` 슬라이스 · `--limit`/`per_page` · `cut -c` · `basename`/`dirname` · 표시 폭 자름.

- ✅ **「없다」를 결론으로 쓰기 «전»에 그 조회에 절단이 있었나를 본다.** 있으면 그건 「없다」가 아니라 **「못 봤다」**다.
- ✅ **찾는 게 «문자열»이면 자르지 말고 «전문에서 센다»** — `select(.body|test("키워드"))` 로 **먼저 걸러낸 뒤** 눈으로 읽는다.
- 🔴 **두 번 자를 때 특히 조용하다** — 첫 자름엔 자각이 남는데 **둘째는 첫 결과에 대고 거는 것이라 원본이 이미 사라진 줄 모른다.** 그리고 잘린 출력은 **여전히 「내용이 있어」 보인다**(빈 출력이면 의심한다).

자름은 출력을 자르는 게 아니라 **실행을 자른다** — 뒤따르는 write·rc 가 사라진다.

```bash
# ❌ 경고가 잘려서 안 들린다
some-check.sh | head -8

# ✅ 절만 뽑거나 파일로 받는다
some-check.sh | awk '/^== 섹션/,/^$/'
some-check.sh > /tmp/out.txt; grep -n '⚠️\|🔴' /tmp/out.txt
```
길이가 문제면 **자르지 말고 골라낸다.** 「짧으니까 괜찮겠지」가 판정이고, 판정은 샌다.

## 3. **극단값**을 보면 대조군을 넣는다 (0 이든 90% 든, 수상할 때가 아니라 매번)

`0건`은 두 가지다 — **깨끗하거나, 검사가 죽었거나.**
**높은 비율도 두 가지다** — 진짜 그렇거나, **마커가 아무 데나 있거나.**

```bash
# 아래로 샐 때: 잡아야 마땅한 가짜 케이스를 넣고 걸리는지 본다
# 위로 샐 때 : 그 마커가 「관계없는 항목」에도 뜨는지 센다 (분모 전체에 돌려본다)
```
실측 2026-08-01 — 같은 날 **양방향으로 다 겪었다.**
`⇒` 가 항목의 93% 를 매치해 **0/0/0** · 「룬드」가 84 중 **77(92%)** 을 매치해 귀속 판정이 무효.
⚠️ **사람 이름·자주 쓰는 기호는 마커로 쓰지 않는다** — 그 코퍼스가 그 사람과의 대화면 분모 전체에 있다.

```bash
# 검사가 잡아야 마땅한 가짜 케이스를 하나 넣어보고, 걸리는지 본다
# 안 걸리면 그 0 은 「깨끗함」이 아니라 「전부 통과시킴」이다
```
실측: 정규식 하나가 항목의 93% 를 매치해 **0/0/0** 이 나왔다. 항진명제였다.

### 3-b. 대조군을 **넣기 전에, 끌 수 있는지** 본다

대조군을 넣었는데 배선이 그걸 조용히 실험군으로 접는 자리가 따로 있다.
**델타 0 을 「효과 없음」으로 읽기 전에 이걸 먼저 의심한다.**

```bash
export VAR="${VAR:-기본값}"   # ❌ 빈 값을 「안 준 것」으로 접는다 → VAR='' 가 기본값이 된다
export VAR="기본값"           # ❌ 무조건 대입 — 아예 밖에서 못 끈다
export VAR="${VAR-기본값}"    # ✅ 하이픈만. 빈 값 = 끔 → 대조군을 만들 수 있다
```
🔴 2026-08-02 **양봇에서 겹쳐 나왔다.** 니노 `WIKI_ORPHAN_EXCLUDES`(`:-`) 는 A·B 가 **글자까지 같은 출력**,
룬드 `SIZE_BASELINE`(무조건 대입) 은 면제 **7=7**. 둘 다 **델타 0** 이었고 둘 다 「효과 없음」으로 읽힐 뻔했다.
고친 뒤 진짜 델타: 니노 162개·고아 5 → 148개·고아 0 / 룬드 면제 0·정식 9 → 면제 7.

⚠️ **「밖에서 준 값은 안 덮는다」 시험은 이 결함을 통과시킨다** — 비어있지 않은 값만 보기 때문.
「빈 값으로 꺼진다」를 **별도 케이스**로 둔다. 변이로 확인: `-` → `:-` 되돌려 그 케이스만 빨개지는지.

## 3-1. 🔴 대조군은 «내 좌변이 잡는 실패»를 심게 되어 있다

변이를 «고르는 손»이 좌변을 이미 알기 때문이다. 그래서 「대조군을 넣었다」가
**축 하나를 재고 나머지를 안 잰 상태**와 구별이 안 된다.

⇒ 물을 것은 **「대조군을 넣었나」가 아니라 「이 대조군이 «내 좌변이 못 보는» 실패인가」**다.

🔑 **판별은 그 자리에서 끝난다 — 변이를 심고 «내 검사가 초록이면» 그게 값 있는 대조군이다**
(빨개지면 이미 보는 축이라 아무것도 안 늘었다).

실물(2026-08-15, 원장 사슬): 대조군으로 **중간 행의 좌변을 `deadbee` 로** 바꿔 1건 검출을
확인했다 — 그런데 **실제 고장은 「행 누락」**이었고 그건 **내부 정합성을 «안 깬다».**
즉 심은 변이는 「좌변 오기입」축이고 진짜 구멍은 「행 누락」축이라, **대조군이 살아 있는 채로
구멍이 그대로 있었다.** 「행 누락」을 심었다면 검사가 **초록**을 냈을 것이고 비용은 한 줄이었다.

🔴 **그리고 한 겹 더 — 판별식이 있어도 «변이 집합»이 좌변에서 나온다.**
실물: `merge-ledger-selfcheck.test.sh` 에는 **위 판별식이 이미 구현돼 있었다**
(*「떨어진 복붙은 dups_any «만» 문다 — 축③ 은 못 본다」* = 심고 초록을 단언). **그래도
행 누락은 샜다.** 가른 것은 「규칙이 있나」가 아니라 **심은 변이가 «복붙 · 떨어진 복붙»
둘뿐이었다는 것** — 전부 「행이 «는다»」 모양이고 **「행이 «준다»」는 한 번도 안 심었다.**

🔴 **그리고 «한 종류»를 심는 것으로도 부족하다 — 종류 안에 «꼴»이 또 있다.**
「행 삭제」를 실제로 심어보니 둘이었고 **값이 정반대**였다(2026-08-15 실측):

```
C 생짜 삭제     다음 행 좌변이 붕 뜬다          → 사슬이 문다      ← 이미 보는 축 = 값 0
D 봉합된 삭제   다음 행 좌변을 앞 행 것으로 고침 → 사슬은 «초록»    ← 실사고의 그 꼴
```

🔑 **현실이 D 를 낳는 이유는 구조다** — 행을 안 적으면 다음 사람이 **「그 문서의
마지막 줄」을 읽어** 좌변에 적으므로 **사슬이 저절로 봉합된다.** C 는 손으로 만들어야
나온다. ⇒ **심을 땐 「현실이 이 종류를 «어떤 손»으로 만드나」를 먼저 묻는다** — 그 손이
만드는 꼴이 값 있는 쪽이고, 내가 편하게 만드는 꼴은 대개 이미 보는 축이다.

⇒ **생성기를 좌변 «밖»에서 가져온다 — 「대상이 겪을 수 있는 상태 변화 전수」.**
원장이면 **추가 · «삭제» · 수정 · 순서 바꿈** 넷. 🔑 **이 목록은 검사기를 «안 보고»
만들 수 있고, 그게 「밖」의 뜻이다.** 판별식은 «고른 뒤»를 재고, 이건 «고르기 전»이다.

🔸 「검사기는 «잘못 쓴 것»이 아니라 «내가 아는 모양»을 잡는다」가 **대조군 층에서** 난 판이다.

## 3-2. 센 수는 **다른 층에서 한 번 더** 본다 — 「그럴듯한 수」는 안 다시 세게 된다

🔴 실물(2026-08-15): `sum(len(v) for v in real)` 로 적었는데 **dict 를 돌면 «키»가 나온다**
— 파일명 문자열의 길이가 더해져 **342** 라는 «그럴듯한» 수가 찍혔다(참값 13).

걸린 경로는 단언이 아니라 **같이 찍어둔 파일별 목록**(1·2·1…)이었다. 합이 그 목록과
안 맞아서 보였다.

⇒ **총합을 낼 땐 «내역»도 같이 찍는다.** 총합만 있으면 검산할 좌변이 없고,
🔑 **틀린 총합은 「틀려 보이지」 않는다** — 자릿수만 맞으면 통과한다.
🔸 계약의 *「수를 «적을» 때는 분모·좌변·그걸 돌린 물건 셋을 같이 적는다」*의 **실행 형태**다.

## 3-3. 한글 파일에서 «글자»와 «바이트»를 나란히 놓지 않는다 (3배 차이다)

```
python3 -c 'print(len(open(f).read()))'   →  18,721   ← «글자»
wc -c f                                   →  34,982   ← «바이트»
```

🔴 실물(2026-08-15): 앞뒤를 이 둘로 재고 **「16KB 가 사라졌다」**로 읽어 데이터 손실을
쫓을 뻔했다. 한글은 UTF-8 에서 **3바이트/글자**라 비율이 그대로 나온다.

⚠️ **한도는 «바이트»로 온다** — MEMORY.md 읽기 한도(24.4KB)·훅 경고가 전부 바이트다.
파이썬으로 재려면 `len(s.encode())`.
⇒ **앞뒤를 비교할 땐 «같은 명령»으로 두 번 잰다.** 도구를 바꾸면 단위가 조용히 바뀐다.

## 4. `0` 을 낼 땐 **훑은 층**을 같이 적는다

얕게 훑은 0 은 깊게 훑은 0 처럼 읽힌다.

## 5. 보내기·커밋 메시지는 **항상** 파일/heredoc

```bash
# ✅ 전송
read -r -d '' P <<'EOF'
본문 (백틱·$·% 안전)
EOF
./src/discord-send <대상> "$P"

# ✅ 커밋
git commit -F msgfile.txt <파일...>
```
길이와 무관하게 항상. 「짧으니까 인라인」이 판정이고, 실측 실패는 전부 그 자리에서 났다.

🔴 **«값을 끼워야 할 때»가 이 규칙의 구멍이다 — 따옴표를 떼지 말고 «자리표시자»를 치환한다.**
`<<'EOF'` 는 안전한데 `${sha}` 를 넣으려고 `<<EOF` 로 바꾸는 순간 **본문의 백틱이 명령으로 실행된다.**

```bash
# 🔴 이렇게 하면 본문의 `abc1234` 가 «실행»돼 그 자리가 통째로 빈다
cat > body.md <<EOF
approve(`abc1234`)가 낡는다      ← sha 가 사라진 채로 발송된다
EOF

# ✅ 따옴표는 그대로 두고 자리표시자만 바꾼다
cat > body.md <<'EOF'
측정: __HEAD__
approve(`__PREV__`)가 낡는다
EOF
python3 - <<'PY'
t = open('body.md', encoding='utf-8').read()
open('body.md','w',encoding='utf-8').write(t.replace('__HEAD__', H).replace('__PREV__', P))
PY
```
🔑 **실패가 조용하다** — 셸은 없는 명령에 `command not found` 를 «stderr 로» 흘리고 본문은 그냥 «빈 자리»로 발송된다. 보낸 쪽은 성공으로 보인다(2026-08-15 실물: PR 코멘트에서 sha 가 먹혀 `네 approve()가 낡는다` 로 나갔다).
🔑 **형식을 계약에 넣을 때 「그 형식을 쓰는 손이 무엇을 하게 되는가」를 같이 본다** — `측정: <sha>` 처럼 «값을 끼우는» 형식은 그 자체로 heredoc 을 열게 만든다.
⚠️ 본문 맨 앞에 `@니노` 를 쓰면 **내 ID 로 매핑**돼 상대 멘션이 안 간다. 본문에 내 이름을 쓰지 않는다.

## 6. `git commit <pathspec>` 은 **부분 커밋**이다

`git commit -m msg file.sh` 는 유효 문법이라 **조용히 그 파일만** 커밋된다.
의도한 파일을 **전부 나열**하고, 직후 `git show --stat HEAD` 로 실제 들어간 목록을 본다.
이 레포에서 `git add -A` 는 쓰지 않는다.

## 7. 「막힘」은 **착수/완료를 나눠서** 적는다

```
착수 막힘: ___     ← 비어 있으면 지금 시작할 수 있다
완료 막힘: ___     ← 승인·확인은 대개 여기다
```
승인은 **머지 조건**이지 착수 조건이 아니다. 한 칸만 두면 완료 막힘이 착수까지 막는다.

## 7-1. 막힘엔 **「다음에 이걸 재는 주어·계기·수신자」**를 같이 적는다

§7 과 **직교**다 — §7 은 *「이 막힘이 «어디까지» 막나」*(내 다음 동작의 **범위**)라 답이
**내 쪽 동사**고, 이 칸은 *「이 막힘이 «누구 손에» 있나」*라 답이 **남의 주어**다.
그래서 §7 «안»이 아니라 «옆»에 둔다(안에 넣으면 「내 동사」 축으로 빨려 들어간다).

```
푸는 조건 : ___     ← 값형으로 (「7일 예상 94% 이하」)
누가 재나 : ___     ← 주어
언제 재나 : ___     ← 계기 (「다음 idle 틱에서 한 번」)
누구에게  : ___     ← 수신자 (「열리면 그 자리에서 상대에게」)
```

🔴 **「조건을 적어두면 조건이 차는 날 저절로 열린다」는 거짓이다.** 조건의 충족은
**관측되어야** 알려지고, 관측에는 주어가 있다. 재는 손이 상대뿐인데 내가 폴링을
안 하기로 했으면 **아무도 안 재는 상태**가 성립한다 — 그리고 그 비용은 **기다리는
쪽에서** 난다(상대는 내가 말해주기 전엔 모른다).

실물 2026-08-11: 룬드 게이트가 닫혀 내 PR 넷의 리뷰가 멈췄는데, 재조회 하한만
값형으로 있고 «누가 다음에 재나»가 없었다. §7 로는 「착수 막힘 비었음 → 딴 거 해라」
까지 나오지만 **「그래서 열린 걸 누가 알려주나」를 §7 은 아예 안 묻는다.**
유래: 룬드↔니노 합의 2026-08-11(그의 `5a592ed`), 경위 inbox `#0811-70`·`#0811-73`.

## 8. 배선까지가 완료

코드가 들어와 있는 것과 **도는 것**은 다르다. 새 검사를 넣으면 **양방향**으로 확인한다.


## 9. 로컬 수정을 «버리기» 전에 — 그게 이미 머지된 것과 같은지 «먼저 조회»한다

`git merge --ff-only` 가 *「local changes would be overwritten」*으로 막히면 손이 바로
`git checkout --` 로 간다. 그런데 그 수정이 **작업 중이던 것**인지 **이미 머지된 것의 사본**인지
그 자리에서는 안 보인다. 판단하지 말고 **한 줄 조회**로 가른다.

```bash
git diff origin/main -- <파일>      # 빈 출력 = 내 로컬이 머지된 판과 «같다» → 버려도 안전
                                    # 출력 있음 = 아직 안 올라간 변경 → 버리면 «없어진다»
```

🔴 **좌변은 `origin/main` 하나가 아니다 — 「어딘가 «닿을 수 있는 곳»에 있나」다.**
실측 2026-08-11: `claude-config/` 5개가 `pull` 을 막고 있었는데 `origin/main` 기준으론
**전부 「출력 있음」**이었다. 그런데 그건 내 작업이 아니라 **크론이 만든 사본**이었고
`origin/chore/claude-config-sync` 에 이미 올라가 있었다. main 만 봤으면 **버리지도
못하고 pull 도 못 하는 교착**이다.

```bash
git fetch -q origin
for r in origin/main origin/<그 브랜치>; do
    git show "$r:<파일>" 2>/dev/null | diff --strip-trailing-cr -q - <파일> >/dev/null \
        && echo "보존됨 $r"
done
```
🔸 `--strip-trailing-cr` 를 빼면 **CRLF 차이만으로 「다름」**이 나온다(그날 2/5 가 그랬다 —
476줄·102줄 차이로 보였는데 개행뿐이었다). 줄끝 때문에 남의 사본을 「고유한 작업」으로
오독하면 지우지도 못하고 쌓인다.
- 🔑 `git diff --stat <파일>`(HEAD 대비)은 **「바뀌었다」만** 말하고 «무엇과 다른가»는 안 말한다.
  좌변을 **`origin/main`** 으로 두어야 「이미 저기 있나」에 답한다
- 🔴 **그 `origin/main` 은 `git fetch` 를 안 하면 «낡은 박제»다** — 이름이 원격처럼 생겨서
  최신처럼 읽힌다. **좌변으로 쓰기 «직전»에 `git fetch -q origin` 을 붙인다.**
  실측 2026-08-11: 남과 공유하는 레포를 **fetch 없이 로컬 작업 트리로** 읽고 「31/34 일치」를
  실측이라 발표했는데, 답이 든 커밋이 **47분 전부터 origin 에 있었다**. 같은 밤 남의 레포는
  `gh api .../contents` 로 조회해놓고 **공유 레포만 맨손**이었다 — 경로 둘, 조심은 하나.
  ⇒ **로컬 작업 트리는 좌변이 아니다.** `git fetch` 후 `origin/main:<경로>` 를 읽거나
  `gh api repos/<o>/<r>/contents/<경로>` 로 조회하고, **좌변에 sha 를 병기**한다.
- 🔴 실측 2026-08-10: `claude-config/hooks/rc-pipe-guard.sh` 가 `M` 이라 ff 가 막혔는데,
  `git diff origin/main` 이 **비어 있었다** — 방금 `#159` 로 머지된 바로 그 내용이었다.
  조회 없이 버렸어도 결과는 같았겠지만, **그건 운이지 절차가 아니다**

## 11. 워크트리를 **셀** 때 — `branch` 줄로 세면 detached 가 통째로 빠진다

```bash
git worktree list --porcelain | grep -c '^worktree '     # ✅ 분모
git worktree list --porcelain | awk '/^branch /'          # ❌ detached 에는 이 줄이 없다
```
- 🔴 실측 2026-08-11 — 「36개」로 승인 요청했는데 실제는 **38개**였다. `awk '/^branch /'` 로 셌고
  detached HEAD 둘에 그 줄이 **아예 없어서** 분모에서 빠졌다. 제거 후 남은 수가 안 맞아서야 잡혔다.
- 🔑 **병의 이름은 「셀 때 쓴 필드가 모든 항목에 있는 게 아니다」**다 — 값이 «틀린» 게 아니라
  **행 자체가 안 나온다.** 필드로 셀 땐 *「이 필드가 없는 항목이 있나」*를 먼저 묻는다.
- 🔸 **「머지됐나」는 `merge-base --is-ancestor` 로 재지 않는다** — squash 는 조상을 안 남긴다(§9 계열).
  좌변은 **PR 상태**다: `gh pr list --state all --json headRefName,state`
- 🔸 **`git worktree remove` 는 브랜치를 안 지운다** — 커밋은 로컬 ref 로 남는다. 그래서 이 정리에서
  잃을 수 있는 건 «커밋 안 된 것»뿐이고, 그건 `git status --porcelain`(untracked 포함)이 덮는다.
  ⇒ **`--porcelain` 이 비었으면 지워도 안전**하다는 말이 여기서 성립한다.

## 13. 셸의 «문자» 연산은 로케일에 매인다 — 그리고 로케일 «이름»은 못 믿는다

`${#s}` · `${s:0:n}` 은 `LC_CTYPE` 이 UTF-8 이 아니면 **바이트**로 센다.

```
LC_CTYPE 비움   ${#가나다}=9   ${T:0:10} = 가나다▒   ← 글자 중간에서 잘린다
C.UTF-8         ${#가나다}=3
```

🔴 **cron · launchd · CI · systemd 는 로케일을 «안» 물려준다.** 그래서 이 병은
**「내 기계에선 된다」로 나타나고, 실제로 깨지는 건 운영 경로**다.

🔴 **`setlocale` 은 «실패해도 경고만 내고 이전 값이 남는다»** — 실측 대조군:

```
export LC_CTYPE=엉터리.XYZ      # bash: warning: setlocale: cannot change locale
echo ${#가}                      # → 1.  «직전 값»이 그대로 산다
```

⇒ **「내가 LC_CTYPE 을 X 로 설정했다」는 X 가 먹었다는 증거가 아니다.**
좌변을 **이름**이 아니라 **성질**로 잡는다:

```bash
_charwise() { local t='가'; (( ${#t} == 1 )); }   # ← 이게 좌변이다
for c in C.UTF-8 en_US.UTF-8 ko_KR.UTF-8; do      # glibc 와 macOS 가 가진 것이 다르다
    export LC_CTYPE="$c"; _charwise && break       # 대입 «뒤»에 매번 다시 잰다
done
```

⚠️ **알고 적어두는 것과 «보장»하는 것은 다른 양이다.** 실물에서 주석이
*「부분문자열은 이 로케일(C.UTF-8)에서 문자 단위다」*라고 **환경 이름까지 붙여
정확히** 적어뒀는데, **그 환경을 강제하는 줄이 0건**이라 그대로 샜다.

🔴 **시험도 «환경을 고정»해야 한다** — 안 하면 돌리는 사람 로케일을 물려받아
**UTF-8 상자에선 고장난 코드가 초록**이다(같은 코드에 두 사람이 다른 색을 봤다).

## 14. `env -u VAR 함수` 는 **조용히 아무것도 안 한다** — `env` 는 셸 함수를 못 본다

```bash
out="$(env -u LANG -u LC_ALL run ...)"   # 🔴 run 이 셸 «함수»면 env 가 못 찾는다
                                         #    → out 이 통째로 빈다
```

그리고 **빈 문자열은 거의 모든 단언을 통과한다** — 「깨진 글자가 없다」·「금지어가
없다」는 **빈 값에서 참**이라, 고장난 대상에 대고도 ✅ 가 난다.

⇒ 서브셸에서 `unset` 한다: `out="$( unset LANG LC_ALL LC_CTYPE; run ... )"`
⇒ 🔴 **그리고 「결과가 비었나」 가지를 «먼저» 둔다.** 3절(대조군)의 특수형이고,
   이 병은 **대조군을 «뒀는데도»** 나므로 따로 적는다.

## 15. 리뷰받은 브랜치에 충돌이 나면 **rebase 말고 merge** (2026-08-15 실물)

- 상황: 인접 삽입 충돌(같은 자리에 두 PR 이 한 줄씩) → 앞 PR 이 머지되고 뒤 PR 이 `mergeable=false`.
- 🔴 **rebase 는 리뷰가 가리키는 커밋을 «지운다»** — 리뷰 본문의 `측정: <sha>` 가 브랜치에서 사라져서 **무엇을 승인했는지 추적이 끊긴다**. 우리 «사건 축»이 rewrite 를 잡으려고 있는데, 그 축을 세워놓고 rewrite 로 푸는 건 앞뒤가 안 맞는다.
- ✅ **`git merge origin/main` + 충돌 해소 + 일반 push** — 리뷰된 커밋이 **조상으로 남고** `head_ref_force_pushed` 도 0건 유지된다.
- ⚠️ **그래도 approve 는 낡는다**(새 커밋이 생겨 시각 축 rc≠0). 내용이 안 바뀌어도 **재승인이 맞다** — 낡은 걸 「내용 같으니 괜찮다」로 접지 않는다.
- 🔸 해소 뒤 반드시 확인: **`git diff origin/main --stat` 이 «해소 전과 같은 순변화»인가**(내 것만 +N, 남의 조항이 안 사라졌나). 충돌 해소는 조용히 남의 줄을 먹을 수 있다.
- 🔸 PR 본문에도 경위를 적는다(「정정은 원 조항을 열어서 고친다」의 적용 — 채팅은 통보지 반영이 아니다).

## 16. 사건 축은 「force-push 가 «있나»」가 아니라 「마지막 «판정» 리뷰 «뒤»에 있나」다

- 실물 2026-08-15 `#230`: `head_ref_force_pushed` **1건**인데 **신선**이었다 —
  `changes_requested 03:01:34Z` → `force-push 03:09:57Z` → `approved 03:12:25Z` 순서라 **판정이 push 뒤**다.
- 🔴 **개수만 세면 「수리 → 재승인」이라는 «정상 경로»가 전부 낡음으로 잡힌다.** 좌변은 **순서**다.
- 🔸 조회: `gh api repos/<o>/<r>/issues/<N>/timeline --paginate` 에서 `head_ref_force_pushed.created_at` 과 `reviewed.submitted_at`(state 가 `approved`·`changes_requested` 인 것만) 을 **시간순으로 나란히** 찍는다. ⚠️ 타임라인 `state` 는 **소문자**다.
